## 结合 Maker 生图的加载界面设计与落地

目标是把加载等待做成游戏自身的门面：**参考资产 → 构图概念 → Maker生成/编辑 → 可用组件 → 真实进度 → 实际画面复查**。不能退化为已有图片拼贴，也不能只交一张无法响应真实状态的概念图。

### 先确定范围

读取现有入口、素材映射和资源加载回调，确认游戏类型、画风、横竖屏、加载阶段、已有Logo与当前问题。只补缺少的决定，不要求用户重填整份问卷。

新增创意图像只使用 Maker MCP 或 Maker 官网。工程负责排版、交互、进度与动效，不能用代码描图替代承诺的 Maker 生图。生成素材不意味着允许更换引擎、初始化Maker项目、构建、提审或发布。

### 按任务读取

- 生图、改图、构图、参考职责与透明组件：[美术与Maker流程](#reference-1)。
- 真实加载、失败重试、入口衔接、性能、验收及案例证据：[集成与验证](#reference-2)。

### 执行顺序

1. **先看真实游戏**：确认不是拿完全不同风格的漂亮图包装较粗糙的游戏。整理少量身份、画风、结构与构图参考，标明每张图的职责。
2. **先画布局再花积分**：确定主体、Logo、进度、提示、错误/重试区域与裁切安全区。提示词中写出需要保持干净的区域，不在生成完才硬塞UI。
3. **用Maker探索整体方案**：可先生成带示意文字/进度的完整概念，但它仅用于设计评审。用户要求选图时展示候选并等待选择；未要求时按明确标准选定，不制造无必要审批。
4. **把方案变成真实资产**：从选定方案生成/编辑无动态文字底图、独立Logo和必要透明装饰。不是所有页面都需要分层，只有需要独立排版/运动的元素才拆；生图返回PNG不代表已有PSD图层。
5. **接入真实加载事件**：进度来自实际工作完成情况；提示文字可游戏化，但不能掩盖失败。达到资源完成后仍要等游戏真正可交互，不能只凭100%数字撤层。
6. **实际页面复查并回改图**：检查手机小屏、短屏、横竖裁切、安全区、文字对比和错误状态。美术问题回到Maker针对修改，不只用代码蒙版补救。

### 不可漏掉的边界

- MCP先核对账号、唯一接收项目和状态；每次传实际项目根 `target_dir`。官网核对同一账号、项目与任务历史。参考目录不是接收项目，缺绑定不自动init或借其他游戏积分。
- 新图走 `generate_image`，独立多图走 `batch_generate_images`，已有图重构/扩图走 `edit_image`。默认图片后端为 `default`，用户指定后才换；以当前schema为准。
- 文字、百分比、存档时间、按钮状态保留真实数据层。静态Logo可用艺术字，但必须逐字校对。
- 不把某个案例的“无总面板、青绿山水、账本”变成所有游戏的审美规则。动作、像素、科幻、恐怖游戏各自沿用其视觉语言。
- 原件与运行时衍生件分开，概念图不进资源清单。素材调用超时先查任务/映射，不能直接重复消费。

### 交付

交付可运行入口及本次所需的素材、参考/生成来源、资源映射、实际尺寸与体积、截图和未完成项。只请求设计时交概念/资产规格，不顺带改游戏。明确分开“Maker生成成功”“页面接入成功”“真实宿主/设备验收成功”。

## 美术与 Maker 生图流程

### 1. 参考与画面合同

记录游戏名、玩家受众、画面方向、现有色板/线条/材质、主体身份、Logo、预计入口状态和输出尺寸。参考图分别标记：身份、画风、结构、构图；不要让一张图同时决定所有事情。

画面合同要回答：玩家先看哪里，视线如何到达进度区；哪些区域可裁，哪些永远保留；哪里适合放动态文本；错误与重试会不会盖住主体。装饰数量、光源和空间关系统一，避免素材相册式摆放。

### 2. 概念探索与最终资源是两步

**概念图**可以完整表现标题、示意进度和按钮，用来比较视觉方案；其中百分比与存档数据都是演示，不能直接烘进正式UI。

**最终素材**根据方案按需生成：
- 背景母版：保留构图与自然留白，不含动态数值和交互按钮。
- 正确标题Logo：需要透明底时单独输出，字形、空白边界和小尺寸可读性合格。
- 前景/角色/光效：确实需要独立运动或适配时才拆出，保持原画透视与边缘。
- 主题进度条组件：外框、填充纹理、游标等可生图；填充长度和进度值由代码驱动，不让图像冒充状态。
- 配套入口插画：例如本地/云端的图标，沿用母版画风，但实际时间与选择结果仍是程序数据。

独立组件不要携带背景平台、伪透明棋盘格、面板外框或多余文字。检查实际alpha，透明PNG的扩展名不是透明证据。深浅底都看边缘，防止白边/黑边与预乘alpha问题。

### 3. 提示词模板

整体概念：
```text
为《[游戏名]》设计[横/竖]屏游戏加载界面概念，[尺寸/比例]。
参考1仅约束[身份]，参考2约束[画风/配色]，参考3约束[场景结构]。
主体[具体情境]，统一[视角、材质、光源]，前中后景清楚，不是素材拼贴。
Logo在[位置]；进度区在[位置]；[区域]自然留白，不是空白矩形。
需兼容[短屏/长屏/裁切方式]，关键主体与标题不能靠边。
[仅概念阶段：示意文字与示意进度]。禁止[无关UI、额外文案、水印、错误人物/道具]。
```

从选定方案提炼组件：
```text
以这张选定概念为唯一视觉基准，提炼[单个Logo/角色/图标/进度条外框]。
保留[颜色、线条、身份和结构]，不要重做成另一种风格。
主体完整且留适量安全边，真正透明背景，无棋盘格、无场景、无额外文字。
不要整页界面、不要拼版。输出[像素尺寸与比例]。
```

底图编辑：
```text
沿用选定场景、主体和光线，去掉示意百分比、进度文字及交互按钮。
保留[区域]的自然干净空间供运行时UI使用，不能留下涂抹痕迹或大白洞。
[新比例]需要重新安排构图/延展背景，不简单拉伸，不裁掉主体。
```

### 4. 两条 Maker 路径

MCP：读取 `maker://status`，不可用用 `maker_status_lite`；记录已确认账号、接收项目根与参考路径。调用示例只作结构，提交前填真实值并核对当期schema：
```json
{
  "name": "game_loading_concept",
  "model": "default",
  "prompt": "[具体构图、参考职责、UI留白和禁止变化]",
  "reference_images": ["assets/image/reference/game-art.png"],
  "aspect_ratio": "9:16",
  "target_size": "1080x1920",
  "resolution": "2K",
  "target_dir": "[已核验Maker绝对项目根]"
}
```
`aspect_ratio`管构图，`target_size`管最终像素，不能用resolution代替后者。透明组件按需加 `transparent=true`。独立候选可以批量；依赖选定母版的衍生件要等母版确定再做。

官网：进入 `https://maker.taptap.cn`，确认账号、项目、参考附件和实际生图/编辑能力，复用相同提示词与验收合同。页面没有精确分层/扩图/透明输出能力时说明限制，不凭空编造按钮；下载正式文件，不拿预览缩略图接入。

输入大小、参考数量、模型和计费跟随运行时规则；普通新图后端默认default，不能从别的游戏继承指定模型或预算。覆盖已有资产与必要本人确认按当前规则执行；不因有“自主完成”要求绕过。生成超时先核查是否已产出，批量部分成功保留成功项。

### 5. 迭代决策

- 主体好看但没地方放字：回改构图/留白，不给所有文字套厚黑框。
- Logo中文错：提供正确名称/已有Logo再编辑，不能用“看起来像”验收。
- 方图适配成竖图丢主体：生成同母版的新构图，不把非等比拉伸当适配。
- 静态图漂亮但加入进度就杂乱：减少装饰、简化进度区；先验完整页面，不只看原图。
- 全新插画过度美化真实游戏：回到实际资源与渲染风格，不制造与进入游戏后的巨大落差。

## 集成、验收与案例证据

### 1. 资产落地

保留Maker原件和映射；将选定图经裁边、缩放、压缩等技术处理得到运行时衍生件，记录来源和哈希，不覆盖供应原件。只把被正式引用的资源加入构建，排除候选、参考图、诊断图和大尺寸原稿。

布局使用明确锚点和安全区；背景可等比cover，Logo/角色常需contain或独立定位。先确定逻辑布局，再处理DPR清晰度，不把物理像素当所有设备的UI单位。背景可裁不代表字、脸和交互区也可以裁。

加载页自身必须足够轻：背景/Logo/关键字体先可显示，其他游戏资源再分批准备。准备失败提供底色/文字Logo等降级，不为展示漂亮加载页再增加一个漫长的无反馈加载阶段。

### 2. 真实状态机

建议显式区分：`boot → preparing → ready`；错误进入`failed`，重试后重新准备。资源完成不是可操作完成，必要的存档恢复、场景构建和首帧准备也应纳入就绪条件。

进度来源可为资源数量或工作量权重，但要注明口径。并发任务完成顺序不同不能导致进度倒退；total=0、未知总量、重复回调都需处理。未知总量用等待状态，不伪造匀速百分比。一个重试attempt内可单调；重试切换要有一致的reset/阶段策略，不能沿用旧100%让用户误解。

运行时提供小而清楚的接口，例如：
```ts
interface LoadingView {
  begin(): void;
  progress(completed: number, total: number): void;
  fail(message: string, retry: () => Promise<void>): void;
  dismiss(): void;
}
```
这是接口示例，不是一套已实现的通用库。准备逻辑、存档和宿主调用由控制层负责，展示层不擅自写档、领奖或选择云档。

- 失败不能停在“快好了”；出现可读错误与重试，诊断信息可折叠。
- 重试按钮防重复触发，取消旧attempt的迟到回调，避免双重启动游戏。
- 撤层不能等装饰动画结束才解锁游戏；过渡期间关闭旧层输入/焦点捕获，动画失败仍能移除。
- 支持reduced-motion；Logo图片失败回退可读文字；进度有必要的无障碍语义。
- 若延展为存档选择页，显示等级/进度/时间，真实备份并由用户选择；漂亮插画不改变冲突处理规则。

### 3. 最小验收矩阵

| 场景 | 检查 |
|---|---|
| 普通首进/缓存命中 | 画面出现及时，真实进度与首次可操作衔接，不闪回旧入口 |
| 慢网/资源失败/重试 | 不假卡100%，不重复初始化；存档不丢；恢复后可玩 |
| 小屏/短屏/长屏/横竖变化 | 主体、Logo、进度、按钮均可读可触达；无拉伸/溢出 |
| 素材或字体缺失 | 有合适降级，文字不消失，不变全屏报错墙 |
| reduced-motion/切后台 | 动画可减弱，不借装饰动画阻止启动，不出现重复音频 |
| 正式构建 | 使用选定运行时图，不包含整套候选和设计控制面板 |

视觉要看实际页面，而非只看生成图。记录画面尺寸、构建身份、截图、资源规格与未决项。自动检查不证明真人审美与手机流畅度。

### 4. 本项目提炼依据与泛化边界

核对日期2026-10-31，来源为项目加载页源码、合同测试及授权分析的2026-10-26素材对话记录：
- Maker批量调用包含独立标题候选、整页加载/存档选择概念；随后基于选定概念提炼两张透明账本插画，而非把整页概念直接当UI。
- 当前 `H5EntryScreens.ts` 使用共享背景、独立Logo和插画；动态进度、存档等级/日期与交互由真实代码绘制。`prepare-brand-assets.mjs` 只准备选定运行时衍生件。
- `H5EntryScreens.test.ts` 覆盖进度边界/单调、真实加载回调、失败重试、透明组件与视觉层不写档；部分是源码合同断言，不等于完整渲染测试。

案例的无总面板、青绿山水与账本只是该游戏设计选择。跨类型提示词、组件合同和测试矩阵是本次泛化，不声称全部题材都实测。公开的是方法与文件名导航，不上传原始对话、私有美术或游戏源码。推荐L2。
