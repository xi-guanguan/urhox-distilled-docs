## TapTap H5 打包、SDK 与 CLI 交付

明确三条链路：**产品构建 → 宿主适配 → 平台包体与发布状态**。每条独立有收据；一条成功不替代另一条。

### 按任务读取

- H5构建、资源/身份、player/review隔离及SDK：[构建与SDK](#reference-1)。
- CLI发现、授权、上传、测试码、草稿与恢复：[CLI与交付](#reference-2)。

### 执行

1. 先确认用户要的是检查、构建、测试上传、扫码、草稿回填还是提审/上线。只做明确范围；“上传文档”不是上传H5游戏授权。
2. 从项目脚本核对构建入口与profile，读工作树、依赖锁、输入/资源清单。只读研究不运行build；实际构建按项目工作流与写入边界执行。
3. 核对目标平台确为TapTap H5，区别微信小游戏、普通浏览器、原生SDK和Maker/UrhoX。Maker仅供素材时不迁移引擎，不调用其远程构建替代H5打包。
4. 用真实项目管线构建并审计最终包：入口、资源路径/哈希、SDK适配、玩家包无调试特权、压缩包根结构与体积。
5. 先做本地/假宿主验证，再在获准的测试包与真实宿主验证。记录两者差异，不把API存在当服务可用，也不从一次失败断言平台永久不支持。
6. 走固定可追踪CLI版本，先help/schema/只读身份核对，再执行获准上传。记录task/version/package三类ID及最终包哈希；超时先查状态，不重复创建版本。
7. 测试码、资格、包体选择、草稿预检、提审与正式发布是不同操作。需要本人授权/确认的停点按实际工具和平台保留，不把历史许可跨游戏继承。

### 常见误区

- 本地源码新不代表旧手机包已更新；同源双包一次成立不代表后续只更新玩家包时验收包也自动变化。
- 浏览器能玩不证明真广告/云档，扫码能进不证明选择了正确普通玩家包。
- CLI的 `--yes` 只是执行参数，不是用户同意。`--dry-run` 也可能读远端元数据，不保证纯离线。
- 不打印/提交PAT、OAuth token、Cookie或登录配置，不把凭证交公共加速镜像。官方CLI与GitHub登录是不同账号会话。

### 交付

给出build/profile/输入与资源摘要、ZIP摘要/字节、实际CLI版本、目标身份、平台version/package、测试码对应ID、验证范围、已知缺口和当前发布状态。没上传/没提审/没发布分别写清；不要用一句“已上线”合并。

## H5 构建与 SDK 接入

### 1. 先辨认运行平台

TapTap H5宿主、微信小游戏、独立Web页面与Maker/UrhoX不是一套API。读项目当前入口与平台适配，不因为用了Maker生图就引入其运行时。SDK全局对象、注入/初始化时机、登录要求及最低宿主版本，按目标平台当期官方文档与实际包信息核对。

本案例从宿主读取 `globalThis.tap` 的广告/云档/生命周期能力；这不是所有Web平台的统一SDK，也不意味着另一个TapTap产品的Web SDK可直接替代。普通浏览器缺该对象时提供合理能力状态，不伪造登录、广告或云保存成功。

### 2. 构建身份与两种包

复用项目已有入口，锁依赖版本，记录构建时间、source commit、dirty输入摘要、profile、输入清单哈希、资源清单哈希、共同玩法摘要。dirty WIP可以被测试，但不能只用旧HEAD假称精确对应。

- player：普通玩家入口，不含场景注入、免广告、自动经营、故障工具和测试档导入。
- review：相同玩法核心加受限验收能力、独立命名空间，默认不接生产云档。

共同玩法哈希的排除范围要列清，只排除纯工具差异，不能把SDK适配或会影响玩家的规则也排掉。哈希匹配是来源证据，不是行为完全等价证明。

检查最终模块图、编译方法和真实行为，不只看源码条件或按钮隐藏。删除调试特权时不得误删真实宿主的广告/领奖能力。对应编译后断言至少覆盖：player无QA特权；真实能力仍启用；review能力不影响正常存档规则。

### 3. 资源与打包

静态资源路径相对目标部署根正确；开发服务器的public路径不一定等于成品包路径。所有正式资源都可读取，不能因404静默退回程序画图却以为美术已生效。构建输出只包含选定资源，不带全部Maker候选、原稿或凭证。

在打包前逐项核对路径、字节与SHA256，打包后抽查/解包验证入口和关键资源；构建后资源变化必须使打包失败。共享资源用链接节省本地空间时，最终ZIP仍要包含真实需要的内容，不能交悬空链接。

本项目TapTap H5打包器使用一个顶层目录：
```text
game-root/
  index.html
  minigame-assets/
  build-info.json
  resource-manifest.json
```
这是该项目上传解析链路已采用的结构；执行新项目前再按当前官方/CLI校验确认。不是所有平台都用相同根目录。目录名不必沿用原游戏。

单文件HTML只是可选策略，不能无条件把所有纹理/音频内联：考虑首屏下载、解码内存、缓存和平台限制。案例里的250MiB是项目自设打包目标，不是本文认定的统一官方上限；最低宿主版本也不是跨游戏固定值。

ZIP、上传暂存、收据分开保存，先生成不可变包与hash，再上传该精确文件。资料草稿和素材交付目录不能混成包体输入。

### 4. SDK 适配层

领域逻辑依赖小接口，不直接到处调用宿主对象。适配层负责：能力检测、参数转换、生命周期、超时、取消、回调清理与错误解释；领域层负责奖励/订单/存档业务规则。

#### 生命周期
就绪且浏览器可见且宿主可见时才运行，监听要幂等。隐藏时保存、停循环、暂停声音；保存抛错也要执行后续停止逻辑。恢复不重复创建循环，不把用户关闭声音的偏好改回开。真实宿主与浏览器可见性要分别记录，不能只依赖一个DOM事件。

#### 广告等异步宿主请求
区分“方法存在”“本次服务正常”“广告看完且奖励已落档”。每次请求有独立attempt/收据与回调，preparing/opening/playing等阶段可见且有上限。取消、打开失败、结果超时与未看完分开；重试有界，旧回调迟到不能触发新请求领奖。

真实超时用墙钟，不用高速业务时钟。后台JS计时器可能暂停，回前台按deadline复核。只有有效完成结果通过正常幂等/保存路径发奖励；暂时失败不应把真实手机永久降级成“不支持的浏览器”。保存失败、重复关闭、取消后迟到完成都要测试。

这是H5宿主适配经验，不拿Maker的广告配置工具/ID代替当前游戏平台配置；若实际操作Maker SDK，才遵守其专用指南与配置前置要求。

#### 云存档
本地保存、远端上传和远端回读确认分别报告。云包带schema、应用范围、revision/parent、更新时间和真实状态；不能只按设备时间选“最新”。上传成功后回读核对对应revision/内容，考虑并发与旧请求，不因有回调就显示永远成功。

冲突前备份本地，展示可理解的等级/日期/时间并按批准策略选择；未设计可安全合并时不自动合并棋盘。测试档禁云，token和私人数据不进日志。断网/超时有恢复途径，不把“云不可用”伪报为“已经同步”。

### 5. 验证层级与案例

至少分：类型/领域测试 → 假宿主异常时序 → 成品包编译/资源审计 → 浏览器真渲染 → TapTap测试包真实SDK → 手机/跨设备体验。没有跑的层级写NOT_RUN。

案例依据2026-10-31核对的 `vite.h5-player.config.ts`、`player-build-plugin.mjs`、`package-h5.mjs`、`H5RewardedAd.ts`、`H5CloudSave.ts`、`H5GameLifecycle.ts` 与对应测试/既有包体收据。较新本地代码、历史验收包和新玩家包可能并存；不在通用文档里固化某个包ID、账号、广告位或个人测试名单。本文未重新构建/上传游戏。

## TapTap CLI 与交付

### 1. 版本和能力发现

官方入口：`https://developer.taptap.cn/v3/cli/`；源码/说明：`https://github.com/taptap/cli`；SDK/小游戏文档入口：`https://developer.taptap.cn/minigameapidoc/`。具体API按当前目标平台导航，不从不对应的SDK复制方法。

2026-10-31实际核对本机已缓存官方 `@taptap/cli@2026.10.29` 的 `--version`、`--help`、`skills list`、`upload-h5-package --help`、`test-qr-code --help`。这说明本手册命令依据，不宣称该版本永远最新，也不自动升级/安装其他客户端Skill。

优先使用当前已安装的准确CLI；PATH缺命令时从实际安装package.json的bin解析入口，不误把“没上PATH”当没安装。不得读取/打印凭证文件。

只读发现示例：
```bash
taptap-cli --version
taptap-cli --help
taptap-cli skills list
taptap-cli auth status
taptap-cli schema app analyze-app-status
taptap-cli upload-h5-package --help
taptap-cli test-qr-code --help
```
这些是当前版本已核对的命令形态，不能保证未来所有参数不变。缺安装且确需使用时，可从官方来源按确认的固定版本获取，例如 `npx --yes --package @taptap/cli@2026.10.29 taptap-cli --version`；不要用未指定版本的latest替代可追溯构建。

当前CLI附带官方业务Skill：先 `skills list`，只读取当前工作需要的包体/资料/测试计划等说明；不要为做一次上传自动运行update --force改动所有全局Skill。

### 2. 身份和授权

先确认当前TapTap用户、developerId、appId与目标游戏。GitHub登录、Maker PAT和TapTap CLI OAuth是不同表面，不能互相代替。

设备授权/二维码/验证码由本人完成，不索取聊天中的token。过期授权要明确旧链接已过期；按用户决定重新发起，不循环刷授权、不强行替人批准。只读身份失败不自动创建新游戏、切服务环境或重置配置。

现有可用账号沿用；只有目标不明/冲突/要求切换时询问。CLI本身提供dry-run/yes不代表用户允许真实写入。

### 3. H5上传

先核对ZIP实际文件、sha256、profile、游戏范围和方向。本次核对的CLI要求输入路径位于当前工作目录内：绝对路径、`..`及解析后越界符号链接会被拒绝。可在有意选定的安全暂存目录复制精确包体，核对复制前后哈希，再从该目录用相对路径执行；不要把用户全盘文件都设为可上传范围。

预演结构示例（变量须由已确认信息填入）：
```bash
taptap-cli upload-h5-package "$ZIP_REL" \
  --dev-id "$DEV_ID" --app-id "$APP_ID" \
  --screen-orientation 1 --dry-run --json
```
本版本方向值0横屏、1竖屏，示例1不适用于所有游戏。dry-run可能读取实时元数据，不写包体不代表绝对离线。

**仅当用户明确要求真实上传且范围已确认**，才执行：
```bash
taptap-cli upload-h5-package "$ZIP_REL" \
  --dev-id "$DEV_ID" --app-id "$APP_ID" \
  --screen-orientation 1 --idempotency-key "$WRITE_INTENT" --yes --json
```
`--yes`只能表达已获得的同意，不替本人作同意。重试同一上传意图沿用稳定幂等key，不能随机换key反复创建版本。不同包/hash是不同意图，应重新核对范围。

任务pending/超时先保留task ID，按当前 `task --help` 查状态/恢复。不同阶段分别记：传输、解析、版本创建、草稿绑定。请求中断不等于远端没成功；查到最终结果前不重复发上传。

### 4. 包体、测试码与资格

解析实际JSON外壳、错误和返回data，区分 `task_id`、version ID与package ID，不把三者混用。上传成功后核对游戏、profile与远端包信息，再交测试入口。

当前自测码命令示例：
```bash
taptap-cli test-qr-code --dev-id "$DEV_ID" --app-id "$APP_ID" \
  --data '{"package_id":123456}' --output test-qr.png --json
```
123456是占位示例，必须换成实际package ID，不是版本ID；输出路径是当前目录内相对路径。不要自动force覆盖已有码。只有本次需要扫码时才调用，不能把码生成当上传/SDK接入必需前置。

扫码能否打开还可能取决于游戏/平台/测试用户资格与包状态。核对已有名单与该平台规则；用户未明确提供账号ID时不猜，不清空其他测试人，不为H5自测盲目创建不相关测试计划。

手机实际显示版本与收据一致后再验SDK。player/review双码明确命名，不能把免广验收包发成普通玩家包。

### 5. 草稿、预检、审核与发布时间

有明确资料回填授权后，先读现有草稿和包体槽位，防止仍绑定旧包、错误profile或“过审即发”。改后回读，按当前 `schema` 获取字段，不猜JSON键。

资料/包体上传、选择主包、预约、预检、最终提审、正式上线/定时上线分别授权与报告。预计发行日期不是定时开放游玩；预约页通过不是游戏已开放。日期写绝对日期和时区，协议/最终提交按平台要求保留本人确认。

预检0阻断/0警告不等于审核通过，二维码成功不等于正式发布。没有完成哪一步就如实写未执行。

### 6. 收据与故障恢复

收据最少有：CLI版本、目标范围、操作意图、输入build/profile/ZIP hash、平台task/version/package、输出/测试码位置、当前状态、实际验证层级、未决项。不写token、Cookie、完整登录配置或个人名单。

分别诊断：PATH/启动器、登录、权限/目标、输入路径/ZIP、编译/资源、远端解析、网络超时与真实SDK。某个表面失败不表示其他会话也失效。使用官方连接与已有授权，不把认证发送公共镜像；只读镜像只能辅助读取公开资料，不能当认证写入端。

本次蒸馏只执行了本地CLI版本/帮助/能力读取，没有登录、上传H5、生成测试码或改发布草稿。核心流程有既有项目收据，跨项目模板与新版CLI组合按执行时规则复核；推荐L2。
