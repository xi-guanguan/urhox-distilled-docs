## 游戏验收页面与真实游戏集成

验收页是通往真实产品与证据的入口，不是另一套演示游戏。复用产品渲染、交互和业务规则，测试能力只提供可控前态、有限动作、故障与观察。

### 按需阅读

- 场景、bridge、命名空间、构建隔离：[集成与权限边界](#reference-2)。
- 身份、证据类型、人工验收与交付：[证据与验收](#reference-1)。

### 最短实施流程

1. 确定本轮需要人验的现象、自动可验证的合同和真实宿主要求；已有场景优先复用，不把大厅扩成开发控制台全集。
2. 验收入口加载真实游戏实例。定义受限bridge：选择批准场景、有限合法动作、只读快照、故障开关和导出；不提供任意eval或无限写状态。
3. 场景前态、测试存档、报告、归档与策略全部隔离。默认禁止人工测试档写真实云端；玩家档导入只读复制。
4. 将结果绑定当前构建、输入清单、资源清单、共同玩法摘要和视口。身份变化旧结果失效，不把以前的PASS搬到新包。
5. 区分模型、合同、GUI自动化、人工体验和真实宿主证据；场景载入、点按钮、导出截图本身不等于验收通过。
6. 在构建阶段剔除玩家包中的测试bridge、前态、特权方法和数据；检测最终依赖图与编译行为，不能只隐藏入口。

### 约束

- 验收工具不重写游戏规则来配合演示；测试模拟广告不能显示“真实广告已通过”。
- 查询参数是场景选择提示，不是权限边界，也不是不可变版本号。
- 浏览器操作、存档导入/重置、真实广告和云端写入仍按本次授权；不能利用bridge绕过Maker画布等要求本人操作的规则。
- 控件折叠且可触达，不能遮住游戏要验的区域；避免不停加载/刷新迫使用户重玩。
- 自动化通过有自己的日志/断言，不借人工PASS按钮冒充真人体验。

### 交付

提供对应版本的入口、简明操作步骤、场景与重现前态、身份/哈希、证据、已知问题及仍需本人操作项。默认不替用户勾“全部通过”、不自动发测试资格、提审或发布。只在本次产生稳定项目事实时更新已有交接，不能把验收大厅当事实源的替代品。

## 身份、证据与交付

### 1. 结果必须绑定版本

一个可复核的身份可包含：
```json
{
  "buildId": "[实际构建标识]",
  "inputManifestHash": "[真实输入清单SHA256]",
  "resourceManifestHash": "[真实资源清单SHA256]",
  "commonGameplayHash": "[明确定义口径的共同玩法摘要]"
}
```
这是待填结构，不是有效哈希。buildId字符串或URL的 `?v=...` 不能替代输入/资源身份。工作树dirty时记录未提交输入摘要，不能只用旧HEAD冒充源码。

报告身份与当前构建不一致时标为 `INVALIDATED`；未执行 `NOT_RUN`、失败 `FAIL`、通过 `PASS` 分开。后续修了代码不能自动把旧截图/旧PASS升级为新版本证据。页面已打开的旧JS也不会因修改URL文字自动热换。

### 2. 各类证据的上限

| 证据 | 能支持 | 不能直接支持 |
|---|---|---|
| 模型/领域测试 | 状态转换与不变量 | 真实渲染、手感、手机SDK |
| 源码合同/编译测试 | 接线、剔除和编译行为 | 玩家实际看见什么 |
| GUI自动化/白盒场景 | 对应构建与前态的操作/画面结果 | 自然成长、真人审美与完整实机 |
| 人工试玩 | 该人实际体验过的路径 | 未触达的系统、全量回归 |
| 真机/真实宿主证据 | 对应平台版本、设备与实际回调 | 其他包/设备/账号一定正常 |

要验证手机广告、跨设备云档等，需对应平台日志/录像/两端数据。大厅一个“通过”按钮不能代替外部事实。自动化入口不改写人工完成身份。

### 3. 结果记录

记录场景ID、构建身份、前态来源、视口/DPR/Canvas实际区域、操作序列、前后快照、截图及时间、executor/evidenceLevel、预期断言与真实结果、阻塞原因。

人工项先做动作再记录结果；仅载入前态或点“通过”没有证明力。自动项用专门断言与收据，不要求全部假扮成一套人工表单。真实宿主和外部合同项只有关联对应外部证据后才能复核，不放开万能PASS。

场景中存在主动故障时不能记为普通路径成功；预期失败与产品缺陷要分清。预置场景只覆盖其限定范围，不能报告“全游戏无缺陷”。

### 4. 大厅只给用户必要作业

把重复自动检查尽量自动完成，并明确未运行/失败；人验列表只留需要人判断的画面、文字、操作和体验。每项给入口、短步骤、预期与反馈方式，不让用户在几十项内部工程检查里找真正待办。

保留用户已验记录与旧档，不因为新批次无条件清空；版本不匹配显示失效原因。截图拍取实际当前游戏画面，不能拿预生成图或旧样例填证据位。

### 5. 最小验收

检查场景装载/切换/归档、同场景刷新恢复、玩家样本不被覆盖、云写入被阻断、故障清理、视口点击映射、身份缺失/不匹配拒绝PASS、自动与人工身份不混用、player包无特权。

交付入口对应当前真实构建；若只在本地，明确没有手机包更新。页面存在不等于游戏能打开，HTTP200不等于场景可交互；构建成功、上传成功、扫码可进入和人验通过分别记录。

### 6. 本项目证据

2026-10-31核对：`H5ReviewBridge.ts` 接入真实游戏、受限场景/存储/故障/导出；`ReviewNamespace.ts` 维护版本化隔离；`ReviewEvidencePolicy.ts` 对构建身份、失效状态与人工/自动/真实宿主证据作约束；`player-build-plugin.mjs` 检查最终模块图并剔除开发方法；编译边界测试同时验证真宿主能力仍保留。

来源是实际源码、既有测试和交付记录，不把历史某个包的PASS赋给当前WIP。本文结构与跨引擎接口为本次泛化，未本轮重跑游戏回归或真人试玩。推荐L2；公开方法，不公开玩家存档、私有项目源码和认证信息。

## 集成与权限边界

### 1. 一个真实游戏，多种可控入口

产品核心保持一套：领域规则/session → 真实渲染与输入 → 平台适配。验收入口通过可替换的开发能力模块接入，而不是再画一份假棋盘/假菜单。

受限bridge的合同示意：
```ts
type ReviewBridge = {
  loadScenario(id: string): Promise<void>;
  perform(action: AllowedGameAction): Promise<ActionResult>;
  snapshot(): Readonly<GameInspection>;
  setFault(fault: AllowedFault): void;
  exportEvidence(): EvidenceBundle;
};
```
类型是架构示意，AllowedGameAction等必须由项目定义白名单；不要原样照搬为可运行库。读快照仍要去除账号凭证/个人数据。自动化可以驱动批准动作，不获得任意脚本/文件/云端操作能力。

### 2. 场景描述而非随意加资源

场景记录：ID、要验证的问题、前置条件、如何进入、人工操作、预期状态/画面、证据类型和限制。后期前态应符合存档schema与业务不变量；“等级99但未解锁任何必要系统”会制造产品本不存在的bug。

新手自然流程和定向前态分开：前者验证可达性，后者验证边界。直接加载前态不证明玩家正常能达到，也不证明整段经营过程有趣。

场景切换需先暂停、保存/归档当前测试档、卸载监听与异步回调，再装入目标前态。迟到回调必须检查会话/场景身份，不能奖励到另一个场景。场景退出清理故障开关和输入状态，不能携带“写入失败”污染下一项。

### 3. 独立存储

建议键空间包含协议版本和场景ID：测试主档、活动键、报告、自动化日志与归档数据库统一隔离。只清当前场景，不清整个localStorage/IndexedDB。

玩家样本只读复制；导入后标注来源版本与人工前态，不写回源档。测试云适配禁用或使用专门测试后端，不能仅靠界面一句“测试档”就允许生产云同步。重置、迁移和导出失败都给可恢复状态。

模拟宿主/奖励作为单独适配层，遵守真实业务限额与幂等；需要测试无限资源时标记为特权工具，不混入正常轨迹或真实宿主证明。

### 4. 玩家包的编译边界

仅用 `?debug=0`、隐藏按钮、按域名判断是不够的。建议：
- player与review独立入口/profile，在模块解析阶段替换开发模块为无权能实现。
- 验收专属fixture、场景catalog、奖励豁免、快进、故障工具不进入player依赖图。
- 共有Canvas/session里的测试方法也必须从player产物移除或隔离，不能因同一文件被引用而意外携带。
- 对最终依赖图做禁止模块审计；对编译后的真实行为测试，确认测试领奖/场景注入被禁，而真实SDK能力仍保留。

不要用宽泛正则一刀切所有“review”字样，误删生产逻辑。若项目用AST变换，覆盖真实语法形态并测试产物；单看源码中条件存在不是编译证明。

两包记录共同玩法摘要用于确认核心同源，但哈希相同不证明所有平台行为完全一样。资源清单、入口代码和SDK适配差异需分别登记。

### 5. 交互与故障

验收栏默认不抢占游戏空间；宽屏可侧栏，窄屏预留底部区域，实际Canvas尺寸和指针坐标一起更新。展开/收起、旋转、软键盘、长文档返回都不应让点击偏移。

故障可覆盖资源404、解码错误、保存失败、重复/迟到回调等，但其类型/作用域有白名单。安全地验证保存失败：失败动作不发布新状态、不发奖励、不关闭必要窗口，恢复后可重试，不只是观察到一个报错Toast。
