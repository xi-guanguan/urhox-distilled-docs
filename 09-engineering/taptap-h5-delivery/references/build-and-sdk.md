# H5 构建与 SDK 接入

## 1. 先辨认运行平台

TapTap H5宿主、微信小游戏、独立Web页面与Maker/UrhoX不是一套API。读项目当前入口与平台适配，不因为用了Maker生图就引入其运行时。SDK全局对象、注入/初始化时机、登录要求及最低宿主版本，按目标平台当期官方文档与实际包信息核对。

本案例从宿主读取 `globalThis.tap` 的广告/云档/生命周期能力；这不是所有Web平台的统一SDK，也不意味着另一个TapTap产品的Web SDK可直接替代。普通浏览器缺该对象时提供合理能力状态，不伪造登录、广告或云保存成功。

## 2. 构建身份与两种包

复用项目已有入口，锁依赖版本，记录构建时间、source commit、dirty输入摘要、profile、输入清单哈希、资源清单哈希、共同玩法摘要。dirty WIP可以被测试，但不能只用旧HEAD假称精确对应。

- player：普通玩家入口，不含场景注入、免广告、自动经营、故障工具和测试档导入。
- review：相同玩法核心加受限验收能力、独立命名空间，默认不接生产云档。

共同玩法哈希的排除范围要列清，只排除纯工具差异，不能把SDK适配或会影响玩家的规则也排掉。哈希匹配是来源证据，不是行为完全等价证明。

检查最终模块图、编译方法和真实行为，不只看源码条件或按钮隐藏。删除调试特权时不得误删真实宿主的广告/领奖能力。对应编译后断言至少覆盖：player无QA特权；真实能力仍启用；review能力不影响正常存档规则。

## 3. 资源与打包

静态资源路径相对目标部署根正确；开发服务器的public路径不一定等于成品包路径。所有正式资源都可读取，不能因404静默退回程序画图却以为美术已生效。构建输出只包含选定资源，不带全部Maker候选、原稿或凭证。

在打包前逐项核对路径、字节与SHA256，打包后抽查/解包验证入口和关键资源；构建后资源变化必须使打包失败。共享资源用链接节省本地空间时，最终ZIP仍要包含真实需要的内容，不能交悬空链接。

本项目TapTap H5打包器使用一个顶层目录：
```text
game-root/
  index.html
  minigame-assets/
  build-info.json
  resource-manifest.json
```
这是该项目上传解析链路已采用的结构；执行新项目前再按当前官方/CLI校验确认。不是所有平台都用相同根目录。目录名不必沿用原游戏。

单文件HTML只是可选策略，不能无条件把所有纹理/音频内联：考虑首屏下载、解码内存、缓存和平台限制。案例里的250MiB是项目自设打包目标，不是本文认定的统一官方上限；最低宿主版本也不是跨游戏固定值。

ZIP、上传暂存、收据分开保存，先生成不可变包与hash，再上传该精确文件。资料草稿和素材交付目录不能混成包体输入。

## 4. SDK 适配层

领域逻辑依赖小接口，不直接到处调用宿主对象。适配层负责：能力检测、参数转换、生命周期、超时、取消、回调清理与错误解释；领域层负责奖励/订单/存档业务规则。

### 生命周期
就绪且浏览器可见且宿主可见时才运行，监听要幂等。隐藏时保存、停循环、暂停声音；保存抛错也要执行后续停止逻辑。恢复不重复创建循环，不把用户关闭声音的偏好改回开。真实宿主与浏览器可见性要分别记录，不能只依赖一个DOM事件。

### 广告等异步宿主请求
区分“方法存在”“本次服务正常”“广告看完且奖励已落档”。每次请求有独立attempt/收据与回调，preparing/opening/playing等阶段可见且有上限。取消、打开失败、结果超时与未看完分开；重试有界，旧回调迟到不能触发新请求领奖。

真实超时用墙钟，不用高速业务时钟。后台JS计时器可能暂停，回前台按deadline复核。只有有效完成结果通过正常幂等/保存路径发奖励；暂时失败不应把真实手机永久降级成“不支持的浏览器”。保存失败、重复关闭、取消后迟到完成都要测试。

这是H5宿主适配经验，不拿Maker的广告配置工具/ID代替当前游戏平台配置；若实际操作Maker SDK，才遵守其专用指南与配置前置要求。

### 云存档
本地保存、远端上传和远端回读确认分别报告。云包带schema、应用范围、revision/parent、更新时间和真实状态；不能只按设备时间选“最新”。上传成功后回读核对对应revision/内容，考虑并发与旧请求，不因有回调就显示永远成功。

冲突前备份本地，展示可理解的等级/日期/时间并按批准策略选择；未设计可安全合并时不自动合并棋盘。测试档禁云，token和私人数据不进日志。断网/超时有恢复途径，不把“云不可用”伪报为“已经同步”。

## 5. 验证层级与案例

至少分：类型/领域测试 → 假宿主异常时序 → 成品包编译/资源审计 → 浏览器真渲染 → TapTap测试包真实SDK → 手机/跨设备体验。没有跑的层级写NOT_RUN。

案例依据2026-10-31核对的 `vite.h5-player.config.ts`、`player-build-plugin.mjs`、`package-h5.mjs`、`H5RewardedAd.ts`、`H5CloudSave.ts`、`H5GameLifecycle.ts` 与对应测试/既有包体收据。较新本地代码、历史验收包和新玩家包可能并存；不在通用文档里固化某个包ID、账号、广告位或个人测试名单。本文未重新构建/上传游戏。
