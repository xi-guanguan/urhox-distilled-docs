# 长线经营加速模拟

目标不是“把游戏速度调快”，而是用可复现证据回答：玩家为何卡住、经济能否持续、长期定时/奖励是否正确。先复用真实规则与可用测试入口，不默认重写一套平行模拟器。

## 先分清四类工作

| 模式 | 用途与证据边界 |
|---|---|
| 正常规则自动游玩 | 输入合法动作，观察该策略下的成长；不代表所有真人行为 |
| 业务时钟加速 | 同一套时间规则下更快推进；不改变设备/宿主时间 |
| 显式离线/跨日跳跃 | 检查冷却、结算、日切；单独记录，不冒充主动游玩时长 |
| 前态注入/故障注入 | 直接测试后期与异常边界；不能证明到达该前态的自然流程 |

## 按任务读取

- 时钟、CPU背压、规划器、预算与手动接管：[时钟和真实规则](references/clock-and-planner.md)。
- 存档隔离、消费账本、导出、测试与证据：[日志和验证](references/ledger-and-proof.md)。

## 执行

1. 确认要验证的成长目标、终止条件、允许资源/策略、随机性、时间规则与预算。保存输入版本和初始状态；不要只设置“无限运行”。
2. 将业务时间注入既有规则；墙钟只测现实耗时/真实宿主超时，性能时钟只做CPU预算。不要重写全局Date.now、系统日期或宿主超时。
3. 通过真实动作/reducer/session提交合法动作，观察真实成功/失败。规划器只决定下一步，不直接改金币、库存、订单或领奖标记。
4. 实施有背压的时间调度：只推进实际处理过的模拟时间，CPU不足降低实际倍速，不让定时器跑过尚未执行的决策；不积攒后台追赶债。
5. 对模拟状态、策略选项、随机状态和日志使用独立命名空间。玩家档只读复制，禁止写回或同步到真实云端。
6. 用阶段进度、资源收支、等待原因和完整可复现快照判断问题。保存失败、不可解释的状态、超预算或人工接管时暂停，不能吞错继续跑。

## 权限与停止条件

本任务不是免费资源生成器：特权前态、模拟奖励、消费策略要显式标记。真实广告/购买/云档/发帖等外部副作用不随自动游玩开启；模拟广告仅走隔离环境中的真实奖励规则和限额，并明确不是SDK验证。

用户要求“只观察”时不注入、不重置。游戏实现与GUI操作仍按当前项目授权执行；Maker画布等要求本人试玩的环境不能靠本Skill绕过。只请求模型测试时不擅自浏览器代玩。

设置现实耗时/模拟天数/动作数/等级等边界，遇保存失败、长时间零进展、同状态循环、预算问题自动暂停并导出原因，而非反复刷新或无限补资源。

## 交付

报告初态、策略、种子、输入/构建身份、目标倍速与实测倍速、主动模拟时长/跨日跳跃、资源账本、关键卡点和复现文件。明确哪些是正常规则、哪些是特权与模拟宿主。界面体验、真实广告、手机性能和真人耐心仍需对应证据。
