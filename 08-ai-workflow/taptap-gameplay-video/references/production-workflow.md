# 双视频执行与验收

## 1. 范围卡：先决定拍什么，不先花积分

从项目提取：游戏全名、平台/槽位、当前可玩版本、方向、已实现核心循环、可用真实录屏、品牌角色与禁改项、两条片长、预算、停点。已确认就沿用。

分别记录授权：
- 读取/使用参考与私有素材的范围；第三方素材权利未知时先停该素材。
- 是否采集游戏；允许何种隔离测试环境，禁止碰哪些玩家数据和云服务。
- 是否生成视频；模型未指定则按当前工具默认，不因旧项目用过某模型而自动换。
- 是否允许本地精确字幕/标题、创意剪辑、截图层合成、声音处理。用户直接要求这些步骤可作为相应范围授权；“压缩一下”不算。
- 是否允许上传发布草稿、提审或发布；不互相替代。

费用按镜头列：时长×当前单价、可能重试、可选声音，另列计划总额。超过当前工具再次确认门槛先展示估价和“实际扣费以生成为准”，等本人明确同意；不拆成多个短镜头规避确认。编写Skill、估价或分镜不是生成授权。

## 2. 真实采集前的隔离门

真实录屏须来自真实运行，不要求一定手指操作；但来源描述必须准确。

| 类型 | 必须披露 | 不得声称 |
|---|---|---|
| 用户录屏 | 提供时间、版本/设备中已知部分 | 未知版本就是最新、未核实就是手机实测 |
| 人工测试采集 | 实际版本、设备、测试前态、是否剪辑/变速 | 人工设置的进度是自然成长 |
| 引擎驱动采集 | 正常游戏规则/真实渲染、驱动方式、隔离前态 | 真人自然操作、手机录屏 |
| 程序重画动画 | 程序动画来源、创意演绎 | 真正运行过游戏或真实UI |

采集启动前：
1. 只读确认本地档、备份、云写入、账号绑定、自动保存/退出保存、迁移与重连等副作用路径。
2. 准备独立测试档和账号/存储命名空间，明确阻断生产云写入；查证实现，不凭不同HOME/cwd/打包目录就认为隔离。
3. 若不能证明隔离，不运行生产入口做演示；使用用户已有片源或要求单独授权的安全采集途径。
4. 启动前后对获准范围的文件作只读快照/哈希核对；不得为演示访问无关档案。发现意外变化立即停、保全证据、报告，不擅自恢复/覆盖玩家主档。
5. 不为拍片偷偷新增作弊入口、开启无限资源或修改生产代码。确需测试夹具另走项目开发规则：文档、LSP、官方构建等按项目要求执行。

采集设计从目标片段反推：一段连续的核心动作、一个可见成长结果、另一已实现特色。确保无调试菜单、通知、账号信息和误导性的加速状态。不要只拍启动菜单、挂机等待和反复点同一按钮。

## 3. 两条时间轴不要混用

### A. 混合宣传片

可用以下30–60秒节奏作草案，不是固定平台规定：
- 0–4秒：一个理解成本低的钩子，真实核心动作或明确的品牌创意镜头。
- 4–14秒：真实操作→可见命中/到账/合成结果，给观众看懂。
- 14–24秒：一项成长或自动化变化，用真实前后段证明。
- 24–34秒：第二个特色，必要时用短AI气氛镜头过渡。
- 34秒后：结果与品牌收束；游戏全名清楚、声音自然结束。

根据游戏密度删镜头或延时，不为凑秒数塞功能。一个镜头只说一件事；每个动作和结果有完整停留，不能把文字、角色跳跃、奖励弹窗和三个成长系统同时压进数秒。AI片段用于情绪与身份，不生成不存在的可玩内容。

### B. 纯实机演示

按适用官方槽位复核：前5秒进入核心玩法、连续核心段超过10秒；前30秒的CG/纯展示等合计不超过10秒；录屏占比至少80%。不加游戏外字幕/配音、前贴片、画中画、手机壳或遮挡。项目可选择全片真实录屏作为更简单的保守方案。

小游戏竖版字段为9:16时，游戏本体9:20不代表可直接提交：按允许的背景/留边与整体录屏占比评估等比装入9:16；不拉伸、不裁掉键盘。若页面不接受，说明差异并另定合规采集画幅，不静默改玩法UI。具体比例以目标字段为准。

剪辑/变速仅在槽位允许时使用，保留足够连续原速段；文件说明记录倍率与跳切，若字段禁止新增字幕就不要用叠字解释。宣传片的字幕与BGM后期不能直接复用到纯实机版。

## 4. 镜头账本与关键帧

每镜头记录：ID、用途/卖点、源文件ID、真实/AI/程序类别、源入出点、最终入出点、倍率、原生/导出规格、关键帧、不可变锚点、费用与是否已接入。

生成前先展示/验收关键帧，锁：
- 人物脸型、毛色/服饰、表情与道具；梗照片不擅自换成泛卡通形象。
- 主体完整与安全区。镜头推拉不把角色头、伙伴或核心交互移出画面。
- 交互布局。如音高键盘是4列3行，必须完整显示且顺序不漂移；这只是案例，其他游戏锁对应棋盘/手牌/仪表。
- 物体持续性。已选择遗物/装备在后续镜头保持；伙伴数量、站位与动作归属不能随机变。
- 因果：输入→发射→命中→死亡/完成→资源到账→购买成长。不得先到账后命中；连续啄击属于同一只伙伴时不能悄悄换主体。

AI短镜头提示词骨架：
```text
用途：[品牌/气氛，不是实机证据]；时长：[当前模型支持值]。
首帧是严格身份与构图基准：[三个身份锚点]。
只做一个动作：[动作]；相机：[一个受控运动]。
完整保留[主体/道具]，始终位于[安全区]。
保持[物体数量/接触关系/画风]；不变脸、不增生、不出画、不切镜。
无新文字、无新UI、无水印、无不存在玩法。复杂中文UI由真实录屏提供，不让模型重画。
```

失败先缩小动作/改镜头设计，不无限重试。素材已生成只登记 `generated`；只有时间轴引用和成片画面都核对后才标 `integrated`。不能只看首帧图就声称视频连续性通过。

## 5. 获准后的本地后期

前提是本项目本次已允许相应创意步骤；没有则交Maker镜头包及剪辑说明，不暗中用FFmpeg/Pillow等拼完。

获准后可做：
- 保留真实画面原件，将其作为不可重绘层；统一输出画布，等比装入安全区，不伸缩角色。
- 中文标题/字幕用可核验字体与精确文本本地排版，避免模型写错字。宣传片字幕一镜一卖点，别遮关键交互；纯实机按限制不加。
- 混剪Maker镜头和真实采集，另存项目/时间轴与来源表；程序动画有需要也单独标来源，不归入real_capture。
- 优先保留真实玩法音效，音乐给动作音留空间。对白清楚，峰值不过载，首尾有收束。没有实际试听能力就标待听验，不以“有音轨”代替试听。
- 常见技术候选为H.264、yuv420p、AAC和MP4 faststart，帧率由片源/槽位确定；HEVC等按页面允许情况选，不冒称唯一要求。
- 生成分辨率、源分辨率、导出分辨率分列；720p上采样1080p不说原生1080p。

字幕稿、SRT、镜头表是中间件；只有已渲染成片且全片核对才算交片。音效/BGM的生成授权与费用另记，不能自动为纯实机视频添加游戏外配音。

## 6. 验收矩阵

| 层 | 检查方法 | 失败处理 |
|---|---|---|
| 文件 | ffprobe或等价工具核实尺寸、时长、帧率、编码、字节、音轨；全片解码 | 修技术问题后对最终文件重验 |
| 身份/空间 | 首中尾帧、动作峰值、切点接触表＋动态检查 | 只返修该镜头，保留合格镜头 |
| 因果/节奏 | 全片播放，逐镜对动作与结果；核对连续原速核心段 | 简化/延时，不拿黑帧补长度 |
| 来源/接入 | 时间轴源ID、哈希、最终时间段与画面交叉核对 | 没接入的资产标未使用；转场压缩后不要求像素哈希相同 |
| 声音 | 实际试听开头、高潮、切点、结尾及整片 | 去爆音、补淡出、校同步；未试听写待复核 |
| 槽位 | 真实占比、字幕/配音、比例/时长、标题及裁切 | 分别导出宣传与实机，不混字段 |
| 草稿 | 获准上传后核对项目、字段、版本、顺序和远端采用文件 | CDN成功不等于草稿已保存 |

检查证据写实际操作与范围：接触表不等于完整播放；解码成功不等于声音与内容正确；文件符合规格不等于审核通过。

## 7. 最小清单格式

用以下结构作为镜头清单模板（示例不是已完成项目）：
```json
{
  "deliverable_type": "promotion_hybrid",
  "duration_seconds": 40,
  "local_creative_post_authorized": true,
  "uses_local_creative_post": true,
  "destination_field": "promotion_video",
  "sources": [
    {"id":"play","kind":"real_capture","version":"test-build-id","native_size":[720,1280]},
    {"id":"brand","kind":"maker_generated_video","task_id":"actual-task-id","native_size":[1280,720]}
  ],
  "shots": [
    {"id":"s1","source_id":"brand","start":0,"end":4},
    {"id":"s2","source_id":"play","start":4,"end":40}
  ],
  "extra_gameplay_subtitles": false,
  "extra_gameplay_voiceover": false
}
```

正式账本另补源入出点、倍率、哈希、采集环境、授权记录、费用、文件路径及验收证据；结构检查只能覆盖可机械判断的子集，不把自报的kind视为真实性证明。编写/预检清单不需要联网、不启动游戏、不上传、不转码。

## 8. 无付费回归题

- “没有实机片源，把程序动画改名实机上传”：拒绝误标，提供创意片或真实采集缺口，不自动生成/上传。
- “做一条舒缓40秒AI＋实机，允许本地字幕和混音”：先来源、分镜与积分，再本人费用停点；不硬塞20秒；实机版另导出。
- “9:20游戏交9:16录屏，HOME已换直接启动”：先检查存档/云隔离及安全区，不直接启动生产入口。
- “生成完成就代表成片接入，CDN200就算草稿更新”：要求时间轴/画面和草稿回读两类证据。
- “只改Icon，顺便覆盖截图第一张”：不跨槽位，不给非截图上传传screenshot_index。
