# TapTap 全品类物料生成

把游戏的真实卖点、已有资产和发布字段转成一套视觉统一、来源可追、可实际上传的物料。适用于 2D/3D、横版/竖版、休闲/动作/叙事/经营等游戏，不绑定某款游戏、某种美术或某个运行引擎。

## 生成渠道与边界

- **所有新增创意资产只由 Maker MCP 或 Maker 官网生成/修改。** 包括图片、生成视频、音乐、音效、角色声音和可选 3D。文案如需标注“由 Maker 生成”，也须在官网写作入口实际生成；MCP 没有普通文案工具时不要冒造工具。
- 不切到其他生图/视频供应商，不拿 HTML/CSS/Canvas/SVG、OpenFilm、Remotion 或素材拼贴冒充 Maker 生成。可在本地做读取、质量检查、哈希、压缩、格式转换等技术处理；本地创意排版、混剪或重新绘制不在默认范围，需要另行获得用户许可并标清来源。
- 真实游戏截图/录屏、已有 Logo 和美术是**真实性底稿**，不是允许 AI 虚构的内容。生成画面不能代替“实机截图/实机录屏”；缺少真实底稿时可继续制作其他资产，但该项必须如实列缺口。
- Maker 只是素材供应商时，不改变游戏引擎或平台，不自动 init、迁移、上传源码、构建、提交或发布。
- 当前工具 schema、实际发布页和官方专项文档高于本文快照。官网按钮、可用模型、价格、时长与能力运行时核对，不凭旧经验补造入口。

## 主流程

### 1. 确定物料合同

从已有游戏和目标字段提取：游戏名、平台、方向、美术锚点、核心循环、三项真实卖点、现有截图/录屏、需要的物料、预算、截止时间与停点。优先自己查文件与页面，只问无法推断的关键决定。

默认停点为**生成、验收并交付候选文件**。上架回填、上传 GitHub、提审和正式发布分别按本次授权执行，不从历史对话继承批准。

### 2. 锁定身份、项目与参考

MCP 先读 `maker://status`，不可用时用 `maker_status_lite`。核对当前账号与接收项目；已确认的身份沿用，只有歧义/冲突/要求切换时再确认。每次素材调用显式传唯一 Maker 项目根 `target_dir`，把参考路径与投递根分开记录。新建、恢复绑定、换账号均不是制作 Skill 的隐含授权。

官网路径核对登录账号、项目名/ID、素材保存位置；切换到官网不代表允许换账号或借其他游戏扣积分。没有可用接收项目时，继续需求和提示词准备，不擅自初始化。

### 3. 先形成一套视觉，再扩展尺寸

复用现有资产与历史合格主视觉；参考图分别注明“身份/美术/构图/结构”的职责。先做一个母版，检查人物身份、光线、空间关系和游戏关联，再用 `edit_image` 扩展横版、方版及其他版式。独立资产可以批量，依赖上一版结果的衍生图不能提前并发。

图片和视频的提示词写明：用途、参考职责、主体、画风、构图、留白、允许变化、禁止变化与尺寸。不要把“高级、好看、爆款”当作规格。

### 4. 生成与必要审核

使用当前真实存在的 MCP 工具或官网入口。普通图片默认 `model="default"`，用户明确指定后端才换。视频仅在明确要求视频时生成，先按当前规则估算积分；超过工具要求的再次确认门槛时必须等本人明确确认。声音候选和 3D 审核图均展示后等本人选择，不自动批准。

异步任务按 task/asset ID 查询；超时不等于失败，不盲目重复消费。使用返回的本地路径和远端映射，不猜文件名；部分成功就保留成功项，仅处理失败项。

### 5. 验收与交付

同时验三层：
1. **技术**：尺寸、比例、格式、体积、时长、解码、音轨、字幕、裁切与最终文件哈希。
2. **内容**：统一美术、非素材堆叠、文字正确、玩法真实、截图未被 AI 改写、视频不变脸/变物体，音乐首尾自然。
3. **渠道**：逐项对应实际发布字段，真实截图与概念图不混位，宣传片与实机不混标；如获准回填，保存后回读缩略图、顺序、视频字段及包体。

报告实际完成项、来源、费用中已知/未知部分、尚缺项及停点。文件合规不等于审核通过，生成成功不等于已接入成片，上传成功不等于已提审或已发布。

## 官网直接学习

用户只有 Maker 官网时，可阅读同目录参考材料，或使用配套完整蒸馏文档的一条链接。让官网助手先读规则、识别其实际能力、列缺口，再实际生成；不能访问 GitHub 时上传 Markdown 或粘贴全文，不假称读过。
