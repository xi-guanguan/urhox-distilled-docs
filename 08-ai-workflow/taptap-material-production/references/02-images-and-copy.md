# 图片与文案

## 1. 先整理品牌参考，不从杂乱素材开始拼贴

只读与本次物料有关的资产。建立一页小型视觉约束：主色/辅色、线条、材质、视角、光源、人物身份特征、文字风格、Logo 与留白区。标清参考职责：

- 身份参考：脸、发型、服饰、道具不可随意变化。
- 画风参考：线条、色彩、材质和细节密度，不代表照抄构图。
- 结构参考：建筑/武器/车辆/棋盘等的形状，避免生成器“合理化”成另一件物品。
- 构图参考：可借层次和重心，不复制他作品牌、角色、标题或水印。

已有一系列合格宣传图时先复用，不重做成“把素材摆满画布”。图里的物体需要共享空间、透视、光源与叙事关系。

## 2. 覆盖矩阵与制作顺序

| 类别 | 核心验收 | Maker 路径 |
|---|---|---|
| Icon | 小尺寸一眼可辨、视觉焦点少、与游戏一致；商店 Icon 不交透明底 | 单图生成，选定后 edit 迭代 |
| Logo/标题字 | 名称逐字正确，轮廓可读，背景透明需求与 Icon 区分 | Maker 生图/编辑，必要时传已有 Logo 作为参考；不要靠错误字硬交付 |
| 横主视觉 | 一件具体、有游戏关系的事；前中后景和自然留白；仅游戏名 | 先母版，再 Logo/标题编辑版 |
| 方主视觉 | 同一场景/人物/色调，重新安排主体与文字，不粗暴裁切 | 对已验收母版 `edit_image` |
| 商店截图组 | 各讲一个已实现卖点，真实 UI 清楚、同尺寸同向，优先展示玩法 | 真实截图输入；Maker 背景模板/官网排版或可验证保真编辑 |
| 视频封面 | 对应真实成片内容；遵守横/方宣传图字段要求 | 复用合格主视觉的适配版 |
| 活动图/社媒图/横竖海报 | 针对各自渠道的文字、尺寸和行动指引，不套商店禁止额外文字的图 | 从品牌母版衍生，各渠道单独验收 |
| 可选角色、道具、场景、序列帧底稿 | 服务物料或游戏内容，不能顺带扩大为全套游戏资产重做 | 对应图片/3D 流程；动图/帧图能力实际核对 |

## 3. 通用主视觉提示词

```text
为《[游戏名]》制作[渠道/用途]主视觉，尺寸[宽×高]，比例[比例]。
参考图1只用于[角色身份]；图2用于[画风与配色]；图3用于[场景结构]。
具体画面：[主角]正在[与游戏真实体验对应的一个动作/情境]。
画面有[前景]、[中景主体]、[远景]，统一[光源方向、材质、视角]。
构图重心在[位置]，[区域]自然留白用于游戏名，非白洞或空矩形。
必须保留：[人物身份、关键道具、视觉锚点]。
仅允许变化：[镜头、姿态、环境气氛等]。
禁止：[额外人物、错误肢体、现代物件、假UI、水印、二维码、素材相册式拼贴]。
[无字底稿：不要任何文字；或最终版：仅精确写“游戏全名”，无其他文字]。
```

无字母版只是中间件；最终字段要求游戏名时，必须经 Maker 编辑/官网可用排版实际完成文字。不会排对中文字时，提供正确 Logo 参考继续编辑；不能把“后期可加字”当作已完成。

方版编辑示例：

```text
把这张已验收主视觉重构为[1:1，1440×1440]，不是简单裁切。
人物身份、关键道具、光源、画风和场景关系保持一致。
将[主体]移到[位置]，完整保留脸和手；[区域]自然留出游戏名空间。
只调整构图与必要背景延展，不增加功能、角色或文字，不做拼贴。
```

可跨类型替换：动作游戏讲一次可实现的闪避/对抗；赛车讲真实车辆与赛道；解谜讲谜题主题但不假造解法 UI；经营讲玩家经营结果；叙事讲已存在的人物关系。不要把“国风、暖色、蒸笼、合成棋盘”固化成通用默认。

## 4. 真实截图包装：不能让 AI 重画游戏

保留三份并分清文件名：`raw_capture` 真实底稿、`maker_template` 生成背景、`store_final` 最终候选。上传清单只能指向验收过的 `store_final`，避免把原始截图当成包装版提交。

工作步骤：
1. 选择三个不同且已实现的核心场景：主玩法、成长/关卡结果、另一项特色；不要用主菜单/商城凑数。
2. 先核对字段允许的包装程度。通用商店至少 50% 真实画面；小游戏更严格字段则跟随其规则。大标题、装饰背景不是所有截图字段都可以用。
3. Maker 生成与品牌统一的背景模板，说明“不要生成棋盘、界面、按钮或文字；为真实截图留连续干净区域”。
4. 仅当官网实际支持保真图层/排版，才锁定真实截图层完成包装；或以 `edit_image` 尝试背景编辑，明确保护 UI。但**提示词承诺保真不等于像素保真**。
5. 对照原图检查所有数值、格子、道具、文字、手指、菜单边界；如可获取底层图则比较受保护区域像素。AI 改了 UI 的结果淘汰，不能称实机截图。
6. Maker 当前无法保真合成时，交付“真实截图 + Maker 模板 + 未完成原因”，不要自行换成本地 Canvas 拼接。用户另行允许本地精确合成后才做，并明示它是合成技术处理，不是 Maker 一步生成。

若允许标题，每张只讲一个真实卖点，标题与截图互相证明，不写“无限资源、全自动、零等待”等未实现承诺。不要假手机壳，不遮挡关键 UI，不把游戏变成另一种视觉密度。

## 5. 文案全套

| 文案 | 应写内容 | 不该混入 |
|---|---|---|
| 一句话介绍/短卖点 | 玩家动作 + 目标/情绪，一眼知道是什么 | 空泛的“全新沉浸、无限可能” |
| 游戏简介 | 类型、核心循环、可验证的特色；重点放前面 | 未实装功能、联系方式、群号、兑换码、受限外链 |
| 开发者的话 | 真实设计动机与具体小事，有个人语气 | 复制简介、虚构开发经历、模板式卖惨/免责 |
| 更新日志 | 本次版本实际变化，有序简短 | 广告、宣传口号、与版本无关内容 |
| 截图标题/视频旁白/字幕 | 与对应画面一致，少而可读 | 商店主视觉禁用的额外文案、实机字段禁用的新增字幕/配音 |
| 社媒发布文案 | 按发布渠道和受众写 | 把社媒导流话术直接塞进商店字段 |

官网写作提示词：

```text
根据本项目已实现功能，生成[一句话介绍、简介、开发者的话、更新日志]。
核心循环：[动作->反馈->结果]；真实特色：[列表]；玩家受众：[受众]。
口吻：[适合本游戏的具体口吻]，简短自然，用具体动作和小事，不做防御性说明。
简介与开发者的话不要雷同；主要信息优先放前50字。
不虚构经历、不承诺未实现功能、不加联系方式、群号、兑换码或受限链接。
额外风格要求：[例如不使用emoji/短小红书口吻，按本次用户要求填写，不跨游戏强制继承]。
先指出事实不足，不用编造补齐。
```

只写文案不自动改后台。MCP 没有通用文本工具时，最终 Maker 文案走官网；Codex 可做事实清单、检查和提示词准备，但不能把自己写的稿子标成官网生成。
