# TapTap 素材增强

先判断图为什么不成立，再决定沿用、改图还是重做。这个专项只解决视觉质量和参考迁移，不取代全品类制作 Skill 的渠道、预算、审核和交付边界，也不自动触发生成、后期或发布。

## 拿对参考，再决定画什么

1. **从槽位和产品事实出发。** 打开当前版本可用的游戏截图、美术、Logo 或历史合格图。确定这是品牌识别、氛围宣传，还是玩法证据。封面可提炼一幕真实体验，Icon 可以只保留一个符号，游戏库背景可以只提供环境和平台叠加空间；不要求每张图讲完整故事。
2. **每份参考说明它约束什么。** 告诉生成器哪份锁定身份/结构、哪份决定画法、哪份只借构图或留白。以本项目授权素材为准；外部参考只提取抽象关系，不携带角色、品牌、字样和受保护内容。没有可靠身份参考就列缺口，不自行补出“官方”角色或玩法。
3. **把取舍写出来。** 用 `槽位与预览 → 玩家应看懂什么 → 必须保留 → 可以改变 → 如何判错` 写短单。只有需要输入图片时才附图。参考冲突先舍弃低优先级图；不要靠叠更多参考解决冲突。

## 先选最小可行改法

| 观察到的情况 | 做法 | 交付前检查 |
|---|---|---|
| 已有合格图，字段差异只在输出尺寸或字节 | 复用或无损于表达的技术导出 | 实际裁切、叠加和缩略图中焦点与文字仍完整；否则重构 |
| 母版成立，换画幅导致手、道具、标题拥挤，或只有一处具体瑕疵 | 保留关系和身份，用 Maker 编辑重构画幅，或只改坏的那一层 | 并排看母版与候选：该变的变了，已经成立的没漂移 |
| 主体像贴进背景、交互不可信、第一眼读错卖点 | 回到同一真实卖点重做构图；让动作、视线、接触点、尺度及光线讲同一件事 | 不靠标题解释画面；移除不支持该卖点的装饰。平面、像素或抽象风格以其自身空间规则判断 |
| 截图数据、棋盘或界面被重画 | 保留原图或只更换受保护真实截图层之外的包装；字段不允许包装则交原图 | 对照底稿；无法保真则不当实机交付。不要在伪造 UI 上继续修字 |

封面可以先确认一个母版再扩展，不为已有合格系列多做一轮。默认只用 Maker MCP/官网生成或编辑；本地创意后期仍需另行许可并标清来源。未获准且工具做不到时，交付评审、可执行改图指令或缺口，不越权处理。

## 对照成品，而不是只审提示词

- 在目标缩略图、实际裁切或平台叠加位先看：哪里先被看到，是否仍能认出品牌、主动作或符号？再按原尺寸查身份、手和物体的接触、UI 与精确文字。无字槽位检查店招、印章等角落；图有文字时只留该槽位允许且有作用的内容。
- 比较候选时一次只动已定位的问题；只有构图本身不成立才重做整幅。记录 `底稿 → 本次改动 → 看见的差异 → 去留及原因`。合格即停，不靠凑候选数量或主观打分延长制作。
- 参考图片本身是观察材料，不是可上传成品或可供其他项目输入生成的授权。

需要成品对照、正反例或跨题材迁移检查时，读 [素材参考与迁移演练](references/visual-cases.md)。自己项目已有合适参考时不必读取案例。
